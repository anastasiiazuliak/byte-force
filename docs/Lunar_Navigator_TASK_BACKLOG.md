## Незмінні правила продукту

1. Тільки місячна область з доступними перевіреними даними: 80–90°S як базова, точне покриття — за DEM/metadata; Apollo поза її межами не включати до реального наукового analysis.
2. Час — UTC ISO `Z`; JSON — camelCase; висоти в метрах від **перевіреної місячної опорної поверхні**; без земного WGS84/EPSG:3857.
3. Horizons → геометричні Sun/Earth azimuth/elevation; LOLA → рельєфний горизонт. `visible` підтверджується тільки за наявності valid terrain model, інакше `null` + `quality`.
4. 3D-тіні Three.js — презентаційна візуалізація, не доказ реального освітлення точки; потенціал освітлення ≠ електрична потужність, видимість Землі ≠ гарантія радіозв'язку.
5. API P0: `GET /health`, `/config`, `/landing-sites`, `/map/metadata`, `POST /analyze`, `/compare`. Static: `/terrain/...glb`, `/tiles/...webp`. P1 `/ephemeris`, P2 `/illumination/...`.
6. Всі mock-значення позначати DEMO, не підсовувати їх як реальні NASA дані.

## Мінімальний готовий шлях NASA challenge

1. Користувач бачить реальну 3D-сцену полюса (або чесно обмежену підготовлену ділянку), може змінювати камеру і ставити точку A.
2. Вибирає UTC date + duration + step, запускає Analyze.
3. .NET отримує реальні Sun/Earth ephemerides, LOLA висоти та профіль локального горизонту, повертає `samples`, `summary`, `intervals`, `horizon`, `quality`.
4. React показує графіки, точку/горизонт, інтервали та синхронізовану часову шкалу.
5. Додає B (інший кратер або інша дата), отримує порівняння B−A із прозорими умовами/обмеженнями.
6. Публічна demo URL відкривається на ноутбуці й телефоні, наукові джерела вказані.
