## Мета

Побудувати живу 3D-діораму південного полюса замість плоского PNG чи непотрібного глобуса.

## Готовий промт / покрокова реалізація

**Контекст продукту:** NASA Space Apps 2026, Lunar Landing Site Navigator. Регіон — південний полюс Місяця, переважно 80°S–90°S. Головна мета — порівняти 2 сценарії посадки (місце + UTC період), аналізувати Сонце/Землю щодо локального рельєфного горизонту. Стек: React + TS + R3F/Three.js; .NET 8 Web API; NASA JPL Horizons; NASA LOLA GeoTIFF; LROC imagery. Повне ТЗ: `docs/TEAM_SPEC.md` (у пакеті також `TEAM_SPEC.md`), контракти: `contracts/openapi.yaml`.

**Загальні правила для Codex:** перед змінами прочитай TEAM_SPEC і чинну структуру репозиторію; працюй лише у зоні файлів цієї задачі, не переписуй суміжні модулі, не змінюй OpenAPI мовчки. Інтегруй через наявні типи/інтерфейси; відсутню реалізацію суміжного модуля закрий мок-адаптером у власній зоні й задокументуй як integration pending (не зупиняй роботу). Пиши компільований код, unit tests, update README за потреби, не додавай секретів/великих сирих DEM у Git. У production **жодних вигаданих даних NASA**. Візуальні 3D-тіні не замінюють науковий аналіз. Наприкінці повідом: що реалізовано, які файли змінено, команди тестування, що ще заблоковано. Не роби push/merge/deploy без дозволу.

**Зроби наступне:**

1. Почни зі сцени та dev-only placeholder; щойно готовий DATA-03, обов’язково заміни його на справжній GLB із DEM. Використай React Three Fiber + Three.js; завантаж demo GLB із DATA-03 та покажи на темному фоні з нейтральним місячним матеріалом/наявною LROC texture.
2. Налаштуй OrbitControls damping, smooth camera ease-to target, pan, dolly/zoom limits, sensible perspective, збереження камери при ресайзі.
3. Підтримай мишу/тач/trackpad/двопальцевий pan; додай Reset view, top-down view, fit-to-region і keyboard accessibility для основних дій.
4. Не використовуйте фантазійну земну атмосферу/неоновий glow як фізичну властивість Місяця; художнє світло окремо позначати.
5. Створи scene state/camera API для FEUI: `flyTo(location)`, `setSelectedSite(A|B)`, `setTime(t)`, `reset()`; на першому етапі це можуть бути typed callbacks.
6. Додай loading skeleton/fallback при WebGL error, graceful disposal GPU resources, опціонально frameloop=demand для статичних сцен.
7. Зроби дві демонстраційні камери й скріншот із справжнім мешем; не підміняй test mock геометрією в production.

## Критерії приймання (Definition of Done)

- [ ] Реальна 3D-геометрія з демонстраційного DEM, не flat image.
- [ ] Камера плавна на desktop і мобільному touch.
- [ ] Сцена не падає при resize/WebGL unavailable.
- [ ] Є typed interface для інтеграції з UI.
